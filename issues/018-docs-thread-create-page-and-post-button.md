# 018 ［ドキュメント］スレッド作成ページとヘッダーの「投稿する」ボタン

元計画：デザイン修正（2026-10-14 のユーザー指示）。関連：[REQUIREMENTS.md §5・FR-T-5](../docs/REQUIREMENTS.md#64-スレッド)、[ARCHITECTURE.md §5](../docs/ARCHITECTURE.md#5-ルーティング)、[UI_GUIDELINES.md §4.1・§5](../docs/UI_GUIDELINES.md#41-共通)、[IMPLEMENTATION_PLAN.md](../docs/IMPLEMENTATION_PLAN.md)

## Background

現在、スレッド作成フォームはコミュニティページの末尾にあり、送信先は `POST /c/:id/threads`（コミュニティが URL で決まる）である（007）。
これを独立したページにし、全画面のヘッダー右上に「＋ 投稿する」ボタンを置いて、そこから作成ページへ移動できるようにする。
作成ページではプルダウンで投稿先のコミュニティを選び、特定のコミュニティを開いているときはそのコミュニティを初期値にする。
画面・ルーティング・入力項目が変わるため、コード（019）の前にドキュメントを更新する。

- **ARCHITECTURE**
  - §5 ルーティング：作成ページと送信先を決める。推奨案：
    - `GET /t/new?c=:communityId`（`c` は初期値。不正・存在しない値は未選択として扱い、404 にしない）
    - `POST /t`（本文に `community_id`。成功時 303 → `/t/:id`、400 は作成ページを入力値付きで再描画、存在しないコミュニティは 400）
    - `POST /c/:id/threads` を廃止するか残すかを決める（推奨：廃止。送信先を1つにする）
  - 「特定のコミュニティを開いているページ」の定義：コミュニティページ（`/c/:id`）とスレッドページ（`/t/:id`、所属コミュニティ）。それ以外（ホーム・一覧など）は未選択
  - コミュニティが0件のときの作成ページの扱い（コミュニティ作成ページへの案内）
- **UI_GUIDELINES**
  - §4.1 ヘッダーの図に「＋ 投稿する」を追加。モバイルでの配置（ワードマーク・ナビ・表示名と1段に収まるか、アイコンのみにするか）を決める
  - §5 共通部品：`PostButton`（ヘッダーの主要操作）、`Select`（`Field` の選択肢版）を追加
  - アイコンは外部リクエストなしのインライン SVG（§8.1・§8.2）。アイコン単体にする場合は `aria-label` を付ける

## Implementation notes

- プルダウン（`<select>`）は JS なしで動く。初期値はサーバー側で `selected` を付けて決める（クライアント JS は増やさない：ARCHITECTURE §2）。
- 投稿ボタンのリンク先は、レイアウトに「現在のコミュニティ ID」を渡して組み立てる（例：`/t/new?c=12`）。
- コミュニティの並びは一覧と同じ名前順。50字の名前がプルダウンで崩れないことを UI 側で確認する。
