# 017 コミュニティ作成ページの実装

元計画：[016](016-docs-community-create-page.md) で更新した REQUIREMENTS §5・ARCHITECTURE §5・UI_GUIDELINES §4.2

## Background

016 の決定に従い、コミュニティ作成フォームを独立したページにし、コミュニティ一覧には作成ページへのボタンを置く。

## Dependencies

- 016

## Scope

- `GET /c/new`：コミュニティ作成ページ（名前・説明のフォーム。ヘッダー・フッターは共通）
- `POST /c`：成功時は従来どおり 303 → `/c/:id`。400／409 は作成ページを入力値とエラー付きで再描画
- `GET /c`：作成フォームを外し、「コミュニティを作る」ボタン（`/c/new` へのリンク）を置く。空状態の案内も作成ページへ誘導
- ホームの欄外の「最初のコミュニティを作る」リンクなど、既存の `/c#new-community` への導線を `/c/new` に置き換える
- `scripts/design/config.mjs` に作成ページを追加し、UI_GUIDELINES §9 のセルフチェックを行う

## Out of scope

- スレッド作成ページ（019）
- ヘッダーの「投稿する」ボタン（019）

## Implementation notes

- ルート定義の順序に注意する（`/c/new` を `/c/:id` より先に定義。`parseId` は `new` を 404 にするため、順序を誤ると作成ページが 404 になる）。
- 作成ページは `PageHeader`（パンくず：コミュニティ）＋ `Form`（`panel`）で組む。フォームの幅は `--column`。
- 既存の `communities.test.ts` の 400／409 のテストは、再描画先が作成ページになることを確認する形に更新する。

## Acceptance criteria

- [x] `/c` に作成フォームがなく、作成ページへのボタンがある
- [x] `/c/new` で名前・説明を入力して作成でき、作成したコミュニティページへ移動する
- [x] 400／409 では作成ページが入力値とエラー付きで表示される
- [x] セルフチェック（UI_GUIDELINES §9）で対象画面が合格し、`design/rounds/NN/review.md` に記録されている
- [x] 共通 DoD

## Tests（S1：`test/http/communities.test.ts`）

- `GET /c` に `/c/new` へのリンクがあり、`/c` を action とするフォームがない
- `GET /c/new` → 200、名前・説明の入力欄と `/c` へ送るフォームがある
- `POST /c` 名前が空 → 400、作成ページ（一覧ではない）を入力値とエラー付きで再描画
- `POST /c` 同名 → 409、作成ページで理由を表示
- 既存の作成成功・名前順・404 のテストが通る

## 実装メモ

- `GET /c/new` を `/:id` より先に定義。作成ページ `CommunityNewPage`（パンくず・キャンセルあり、ナビは「コミュニティ」を上位の現在地として表示）。
- `/c` から作成フォームを外し、見出しの操作に「コミュニティを作る」ボタン、空状態にも作成ページへのリンクを置いた。ホーム欄外のリンクも `/c/new` に変更。
- セルフチェック：`design/rounds/16/review.md`（合格）。
