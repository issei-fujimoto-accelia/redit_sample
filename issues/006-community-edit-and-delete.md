# 006 コミュニティの修正と削除（スレッドなし）

元計画：[IMPLEMENTATION_PLAN.md W6](../docs/IMPLEMENTATION_PLAN.md#w6-コミュニティの修正と削除スレッドなし)

## Background

作成者本人だけが修正・削除できるという権限ルールを、最初に扱うリソースで確立する。以降のスレッド・投稿でも同じパターンを使う。

## Dependencies

- 005

## Scope

- `POST /c/:id/edit`：名前・説明の修正（303 → `/c/:id`）
- `POST /c/:id/delete`：スレッドのないコミュニティの削除（303 → `/c`）
- コミュニティページの編集フォーム（`<details>`）と削除ボタン（`confirm`）。作成者本人にのみ表示
- 本人以外の修正・削除 → 403

## Out of scope

- スレッドがある場合の削除不可（409）は、スレッドを作れるようになってから 009 で扱う

## Implementation notes

- UPDATE / DELETE 文に `author_email = ?` を含める。0行のときはサービス層で原因（未検出／本人でない）を判別する（ARCHITECTURE §4.4）。
- DELETE 文には「スレッドが存在しない」条件も先に入れておいてよい（テストは 009）。
- 修正では `updated_at` を設定する。

## Acceptance criteria

- [ ] 作成者は名前・説明を修正できる。修正後の名前が他と重複すると 409
- [ ] スレッドのないコミュニティを削除でき、コミュニティ一覧へ移動する
- [ ] 他人には修正・削除の操作が表示されず、直接 POST しても 403 でデータは変わらない
- [ ] 共通 DoD

## Tests（S1：`communities.test.ts`、`security.test.ts`）

- 作成者が修正 → 303、ページに新しい名前・説明
- 修正後の名前が既存と重複（大小文字違い含む）→ 409
- 修正で名前を空 → 400
- 削除 → 303 `/c`、一覧から消え、`/c/:id` が 404
- 他人で GET → 修正・削除の操作が表示されない
- 他人の修正・削除 POST → 403、その後の GET で内容が変わっていない
