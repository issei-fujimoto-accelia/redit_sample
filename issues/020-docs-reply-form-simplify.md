# 020 ［ドキュメント］返信フォームの簡略化

元計画：デザイン修正（2026-10-14 のユーザー指示）。関連：[UI_GUIDELINES.md §4.2・§5・§7](../docs/UI_GUIDELINES.md#5-共通部品)

## Background

スレッドページの返信フォームは「返信する」の見出しと「本文」のラベルを持つ（010）。
会話の流れの中で軽く書き込めるよう、見出しと見えるラベルをなくし、プレースホルダー「会話に参加する」で入力欄の役割を示す形に変える。
UI_GUIDELINES §7 は「フォームはすべてラベル付き」としているため、アクセシビリティ上の扱いを先に文書で決める。

## Dependencies

なし（016・018 と独立。021 の前提）

## Scope

- **UI_GUIDELINES**
  - §4.2 スレッドページ：返信フォームは見出しなし、見えるラベルなし、プレースホルダー「会話に参加する」
  - §5 `Field`：見えるラベルを省略する場合の規則（視覚的に隠したラベル、または `aria-label` で名前を必ず付ける。プレースホルダーをラベルの代わりにしない）
  - §7：上記の例外と、上限文字数の補足・エラー表示を見えるラベルなしでどう示すか（エラー文は従来どおり表示し `aria-describedby` で結ぶ）
- **REQUIREMENTS**：画面の内容の記述に影響があれば更新（返信フォームの存在自体は変わらない）

## Out of scope

- コードの変更（021）

## Implementation notes

- アクセシブルな名前は「返信の本文」などにし、読み上げで役割がわかるようにする。
- 上限文字数の補足（10,000文字まで）を見えるまま残すか、エラー時だけ出すかを決める。

## Acceptance criteria

- [x] 返信フォームの見た目（見出し・ラベル・プレースホルダー）と、アクセシブルな名前の付け方が UI_GUIDELINES に書かれている
- [x] §7 の「すべてラベル付き」との関係が明記されている

## Tests

- ドキュメントのみのため自動テストなし

## 決定事項

- 見出し「返信する」は削除。送信ボタンの文言「返信する」は残す。
- ラベルは視覚的に隠して残す（アクセシブルな名前「返信の本文」）。プレースホルダー「会話に参加する」はラベルの代わりにしない。
- 上限文字数の補足（10,000文字まで）は入力欄の下に見えるまま残す。エラー文は従来どおり表示し `aria-describedby` で結ぶ。
- REQUIREMENTS は返信フォームの有無を変えないため変更なし。
