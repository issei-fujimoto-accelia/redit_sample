# 要件定義（Requirements）

Reddit 風掲示板の要件を定める。前提は `spec/CONCEPT.md`（概念設計）、作成方針は `docs/DOCUMENTATION_PLAN.md` に従う。

## 1. 目的

コミュニティ単位で議論がまとまり、コミュニティを横断してスレッドを発見できる、Reddit 風の掲示板を作る。

- スキル駆動の開発フロー（documentation-planning → document-interview → implementation-planning → issue-planning）を試すためのサンプルとする。
- 核となる体験（**発見**：ホームの横断一覧、**一望**：コミュニティ内一覧）が成り立つ最低限の機能に絞る。
- 長期運用はしない。

## 2. ユーザー

| ユーザー | 説明 |
|---|---|
| ログインユーザー | Cloudflare Access で認証された、特定ドメインの Google アカウントを持つ人。数名程度 |

- 未ログインの閲覧者は存在しない。閲覧を含むすべての操作にログインが必要。
- 管理者ロールは設けない。全ユーザーが同じ権限を持ち、修正・削除は作成者本人のみが行える。

## 3. 用語

| 用語 | 説明 |
|---|---|
| コミュニティ | テーマ単位のまとまり。スレッドを束ねる |
| スレッド | コミュニティに属する議論の単位。タイトルと本文を持つ |
| 本文 | スレッド作成時に入力する最初の投稿 |
| 投稿 | スレッド内の発言。本文を含め、フラットに時系列で並ぶ（ネストなし） |
| 返信 | 本文以外の投稿 |
| 表示名 | 画面に表示するユーザー名。メールアドレスの `@` より前の部分 |
| 最終投稿日時 | スレッド内に残っている投稿のうち、最も新しい作成日時 |

## 4. スコープ

| 対象 | 作成 | 閲覧 | 修正 | 削除 |
|---|---|---|---|---|
| コミュニティ | ○ | ○（一覧／個別ページ） | ○（名前・説明） | ○（スレッドがない場合のみ） |
| スレッド | ○（タイトル＋本文） | ○（ホーム横断一覧／コミュニティ内一覧） | ○（タイトル） | ○（返信がない場合のみ。本文も削除） |
| 投稿 | ○（返信） | ○（スレッド内で古い順） | ○（本文・返信とも） | ○（返信のみ。本文は単独削除不可） |

## 5. 画面とユーザーフロー

### 5.1 画面

| 画面 | 役割 | 内容 |
|---|---|---|
| ホーム | 発見 | 全コミュニティ横断のスレッド一覧（ページング） |
| コミュニティ一覧 | 入口 | コミュニティの一覧と作成フォーム |
| コミュニティページ | 一望 | コミュニティ名・説明、スレッド一覧（ページング）、スレッド作成フォーム |
| スレッドページ | 参加 | タイトル、投稿一覧（本文が先頭）、返信フォーム |

全画面から、ホームとコミュニティ一覧へ移動できる。

### 5.2 主なフロー

```
ホーム ──(スレッド選択)──────────────→ スレッドページ
  │                                       ↑
  └→ コミュニティ一覧 ─(選択)→ コミュニティページ ─(スレッド選択／作成)┘
          │
          └─(作成)→ 作成したコミュニティページ
```

- コミュニティを作成すると、そのコミュニティページへ移動する。
- スレッドを作成すると、そのスレッドページへ移動する。
- 返信を投稿すると、同じスレッドページに留まり、投稿一覧の末尾に追加される。
- スレッドを削除すると、所属するコミュニティページへ移動する。
- コミュニティを削除すると、コミュニティ一覧へ移動する。

## 6. 機能要件

### 6.1 共通

| ID | 要件 |
|---|---|
| FR-C-1 | Cloudflare Access が付与するユーザー情報（メールアドレス）でユーザーを識別する。Access の認証情報を持たないリクエストは拒否する |
| FR-C-2 | 作成者・投稿者は表示名（メールアドレスの `@` より前）で表示する。表示名の設定機能は持たない |
| FR-C-3 | 日時は JST の絶対表示（`YYYY-MM-DD HH:mm`）とする |
| FR-C-4 | 修正・削除の操作は作成者本人にのみ表示する。本人以外からの修正・削除リクエストはサーバー側で拒否する |
| FR-C-5 | 削除の前に確認を求める。削除は物理削除とし、履歴は残さない |
| FR-C-6 | 修正の履歴は残さない |
| FR-C-7 | 存在しないコミュニティ・スレッドを開いた場合は、見つからない旨を表示する |

### 6.2 入力制約

文字数は、前後の空白を除いた後の文字数で数える。

| 項目 | 必須 | 上限 | その他 |
|---|---|---|---|
| コミュニティ名 | ○ | 50文字 | 全コミュニティで一意（作成時・修正時とも） |
| コミュニティ説明 | － | 500文字 | |
| スレッドタイトル | ○ | 200文字 | |
| 投稿本文（本文・返信） | ○ | 10,000文字 | |

- 必須項目が空（空白のみを含む）の場合、または上限を超える場合は保存せず、理由を表示する。
- 本文・説明はプレーンテキストとする。改行は保持し、HTML はエスケープして表示する。

### 6.3 コミュニティ

| ID | 要件 |
|---|---|
| FR-CM-1 | コミュニティ一覧は全コミュニティを名前順で表示する（ページングなし） |
| FR-CM-2 | 名前と説明を入力してコミュニティを作成できる。作成者は作成したユーザーとする |
| FR-CM-3 | 作成者は名前と説明を修正できる |
| FR-CM-4 | 作成者は、スレッドが1件もない場合に限りコミュニティを削除できる。スレッドがある場合は、削除できない理由を表示する |

### 6.4 スレッド

| ID | 要件 |
|---|---|
| FR-T-1 | ホームは全コミュニティのスレッドを、コミュニティページはそのコミュニティのスレッドを一覧表示する |
| FR-T-2 | スレッド一覧は最終投稿日時の新しい順に並べる。同時刻の場合は、後に作成されたスレッドを上にする |
| FR-T-3 | スレッド一覧は1ページ20件でページングする |
| FR-T-4 | スレッド一覧の各行には、タイトル、コミュニティ名（ホームのみ）、作成者、投稿数（本文を含む）、最終投稿日時を表示する |
| FR-T-5 | コミュニティページで、タイトルと本文を同時に入力してスレッドを作成できる。本文はスレッド作成者の投稿として保存する |
| FR-T-6 | 作成者はタイトルを修正できる。修正されたタイトルには「編集済み」を表示する |
| FR-T-7 | 作成者は、返信が1件もない場合に限りスレッドを削除できる。削除時は本文も削除する。返信がある場合は、削除できない理由を表示する |

### 6.5 投稿

| ID | 要件 |
|---|---|
| FR-P-1 | スレッドページは、本文を先頭に、すべての投稿を作成日時の古い順に表示する（ページングなし、ネストなし） |
| FR-P-2 | 各投稿には、投稿者、作成日時、本文を表示する |
| FR-P-3 | スレッドページで返信を投稿できる |
| FR-P-4 | 投稿者は自分の投稿（本文・返信とも）を修正できる。修正された投稿には「編集済み」を表示する |
| FR-P-5 | 投稿者は自分の返信を削除できる。本文は単独では削除できない（削除操作を表示しない） |
| FR-P-6 | 投稿の作成・削除で最終投稿日時が変わる。投稿の修正では変わらない |

## 7. 非機能要件

| ID | 要件 |
|---|---|
| NFR-1 | PC とスマートフォンの最新ブラウザで利用できる。レスポンシブ対応は、スマートフォンで読み書きできる最低限とする |
| NFR-2 | Cloudflare のフリープランの範囲（リクエスト数、D1 の行読み書き数、CPU 時間の上限）に収まる。具体的な上限値は Architecture で最新ドキュメントを確認して記載する |
| NFR-3 | 可用性・性能の数値目標は設けない |
| NFR-4 | 利用者は数名程度を想定し、それを超える負荷への対応は行わない |

## 8. 制約

- Cloudflare のフリープランで構成する（Workers と D1 を中心とする）。
- 認証は Cloudflare Access に任せ、アプリ側で独自の認証機能を持たない。
- アクセスは特定ドメインの Google アカウントに限定する。

## 9. 非スコープ

- 投票（up/down）とスコアによる並び替え
- 投稿のネスト（返信への返信）
- 画像・リンク投稿、Markdown などのリッチテキスト、URL の自動リンク化
- コミュニティへの参加（join）とパーソナライズされたホーム
- モデレーション、管理者機能
- 検索、通知
- 表示名の設定・変更
- スパム対策（レート制限など）
- 未ログインでの閲覧、一般公開
- 独自の認証機能
- 修正・削除の履歴管理
- 大規模運用、長期運用、収益化、モバイルアプリ

## 10. 受け入れ条件

### 認証・権限

- [ ] Access の認証情報を持たないリクエストは拒否される。
- [ ] 投稿者名が、メールアドレスの `@` より前の部分で表示される。
- [ ] 他人のコミュニティ・スレッド・投稿には修正・削除の操作が表示されない。
- [ ] 他人のリソースへの修正・削除リクエストを直接送ると拒否され、データは変わらない。

### コミュニティ

- [ ] 名前と説明を入力してコミュニティを作成でき、作成後にそのコミュニティページへ移動する。
- [ ] 既存と同じ名前では作成・修正できず、理由が表示される。
- [ ] 名前が空、または50文字を超える場合は保存されない。説明が500文字を超える場合も保存されない。
- [ ] コミュニティ一覧が名前順に並ぶ。
- [ ] スレッドがあるコミュニティは削除できず、理由が表示される。スレッドがなければ削除でき、コミュニティ一覧へ移動する。

### スレッド

- [ ] タイトルと本文を入力してスレッドを作成でき、作成後にそのスレッドページへ移動する。本文が先頭の投稿として表示される。
- [ ] タイトルが空・200文字超、本文が空・10,000文字超の場合は保存されない。
- [ ] ホームに全コミュニティのスレッドが、コミュニティページにそのコミュニティのスレッドだけが表示される。
- [ ] スレッド一覧が最終投稿日時の新しい順に並ぶ。古いスレッドに返信すると一覧の先頭に移動する。
- [ ] 最新の返信を削除すると、最終投稿日時がその前の投稿の日時に戻り、並び順に反映される。
- [ ] 投稿の修正では一覧の並び順が変わらない。
- [ ] スレッドが21件以上あるとき、一覧が20件ずつのページに分かれる。
- [ ] 一覧の各行にタイトル、コミュニティ名（ホームのみ）、作成者、投稿数、最終投稿日時が表示される。
- [ ] タイトルを修正すると「編集済み」が表示される。
- [ ] 返信があるスレッドは削除できず、理由が表示される。返信がなければ本文ごと削除でき、コミュニティページへ移動する。

### 投稿

- [ ] 返信を投稿すると、スレッドページの末尾に表示される。
- [ ] 投稿が古い順に並び、ネストされない。
- [ ] 本文・返信を修正すると「編集済み」が表示される。
- [ ] 返信は削除できる。本文には削除操作が表示されない。
- [ ] `<script>` などの HTML を含む投稿が、そのまま文字列として表示される。改行は保持される。

### 表示

- [ ] 日時が JST の `YYYY-MM-DD HH:mm` 形式で表示される。
- [ ] 存在しないコミュニティ・スレッドの URL を開くと、見つからない旨が表示される。
- [ ] スマートフォンの画面幅で、各画面の閲覧と投稿ができる。

## 11. 後続ドキュメントへの引き継ぎ

| 事項 | 引き継ぎ先 |
|---|---|
| フロントエンドの方式（SSR / SPA） | Architecture |
| 表示名のデータ上の持ち方（保存するか、都度メールアドレスから導出するか） | Architecture（Data Design 節） |
| 最終投稿日時・投稿数の算出方法（都度集計か、スレッドに保持するか） | Architecture（Data Design 節） |
| Access JWT の検証方法 | Architecture（Security 節） |
| フリープランの具体的な上限値 | Architecture（Operations 節） |
| 一覧の「同時刻」判定に使う識別子 | Architecture（Data Design 節） |
