# Goal State

## Goal
Reddit 風掲示板の要件を、Architecture / Test Strategy の作成と実装に進める状態まで確定する。

## Deliverable
`docs/REQUIREMENTS.md`

## Scope
- 入力：`spec/CONCEPT.md`（Project Overview 相当）、`docs/DOCUMENTATION_PLAN.md`
- 含める：目的、ユーザー、スコープ、ユースケース、機能要件、非機能要件、制約、非スコープ、受け入れ条件
- DOCUMENTATION_PLAN により含める：UX / User Flow（4画面の遷移）、Privacy（表示名）
- 含めない：SSR/SPA、テーブル定義、ルーティング（Architecture で決める）

## Completion Criteria
- [x] スコープが明確
- [x] 主要機能の振る舞いが明確（作成・閲覧・修正・削除、並び順、削除制約）
- [x] 主要な制約が明確
- [x] 要件が検証可能（受け入れ条件がある）
- [x] 実装を妨げる重大な未決事項がない

## Decision Areas

### A. スレッドの最初の投稿の扱い／スレッド削除の手順
Status: resolved
Known: スレッド作成時にタイトルと最初の投稿を同時入力。投稿が残っているスレッドは削除不可。
Unknown: 最初の投稿は単独で削除できるか。スレッド削除の条件。

### B. ユーザーの表示名
Status: resolved
Unknown: メールアドレスをそのまま表示するか、表示名を持つか。

### C. スパム対策
Status: resolved
Known: Access の内側、数名利用。

### D. 各エンティティの属性と入力制約
Status: resolved
Unknown: コミュニティの属性（名前のみ／説明あり）、名前の一意性、URL 識別子、文字数上限、本文の書式（プレーンテキスト／Markdown）。

### E. 一覧の表示量（ページング）
Status: resolved
Unknown: ページングの有無と件数。無料枠（D1 行読み取り）との関係。

### F. 表示の細部
Status: resolved
Unknown: 編集済み表示、日時表示、空状態、削除不可時の表示。

### G. 非機能要件
Status: resolved
Known: 無料枠内、数名利用、長期運用なし、Access 認証。
Unknown: 対応ブラウザ／端末幅など最低限の水準。

## Decisions
（CONCEPT.md の決定事項 §11 を前提として引き継ぐ）
- A: 最初の投稿はスレッド本文として扱う。本文は単独で削除不可（修正は可）。スレッド作成者は、本文以外の投稿がなければスレッドごと削除できる（本文も物理削除）。
- B: 表示名はメールアドレスの @ より前（ローカル部）。表示名の設定機能は持たない。
- D: コミュニティは名前（必須・一意）と説明（任意）を持つ。修正対象は名前と説明。
- D: 本文はプレーンテキスト（改行保持、HTML はエスケープ）。
- D: 文字数上限 コミュニティ名50／説明500／スレッドタイトル200／投稿本文10,000。前後の空白を除いて空になる入力は不可（説明は空可）。
- E: ページングはスレッド一覧（ホーム、コミュニティページ）のみ。1ページ20件（件数は提案値）。コミュニティ一覧とスレッド内の投稿は全件表示。
- C: スパム対策は不要（レート制限なし）。
- F: コミュニティ一覧は名前順、投稿は古い順。最終投稿日時は残っている投稿の最新作成日時（修正では変わらない）。
- F: スレッド一覧の項目はタイトル、コミュニティ名（ホームのみ）、作成者、投稿数、最終投稿日時。
- F: 修正済みの投稿・タイトルに「編集済み」を表示。日時は JST の絶対表示（YYYY-MM-DD HH:mm）。
- F: 修正・削除の操作は作成者本人にのみ表示し、サーバー側でも拒否。削除は確認を挟む。削除不可の場合は理由を表示。
- G: PC／スマホの最新ブラウザで利用可能（レスポンシブは最低限）。無料枠内で動作。可用性・性能の数値目標は設けない。
