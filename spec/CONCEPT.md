# 概念設計（Concept）

Reddit 風掲示板の概念設計。後続ドキュメント（Requirements、Architecture など）の起点とする。

## 1. 背景

- スキル駆動の開発フロー（documentation-planning → document-interview → implementation-planning → issue-planning）を試すためのサンプルとして作る。
- 長期運用は想定しない。

## 2. 目的

コミュニティ単位で議論がまとまり、横断的にスレッドを発見できる、Reddit 風の掲示板を作る。

Reddit のすべてを再現する必要はなく、核となる体験が成り立つ最低限の機能に絞る。

## 3. プロダクト概要

コミュニティ単位でスレッドを立て、スレッド内で投稿して議論する掲示板。

この掲示板の価値は、次の2つの入口を持つことにある。

- **発見**：ホームで、コミュニティを横断してスレッドを一覧し、新しいスレッドとの出会いを促す。
- **一望**：コミュニティページで、そのコミュニティのスレッドを一覧し、まとまりのある議論を見渡せるようにする。

## 4. 前提・想定

- 利用者は数名程度。
- 長期運用はしない。サンプルアプリとして位置づける。
- Cloudflare Access の内側に置き、特定ドメインの Google アカウントを持つユーザーのみがログインできる。
- 閲覧も含め、すべての操作はログイン済みユーザーが行う。未ログインの閲覧者は存在しない。

## 5. 想定ユーザー

- **ログインユーザー**：Cloudflare Access で認証された、特定ドメインの Google アカウントを持つ人。コミュニティ、スレッド、投稿を閲覧・作成し、自分が作成したものを修正・削除する。

## 6. 主要な概念

```
Community 1 ── * Thread 1 ── * Post
User      1 ── * Community / Thread / Post（作成者）
```

| 概念 | 説明 |
|---|---|
| User | Cloudflare Access で認証されたユーザー |
| Community | テーマ単位のまとまり。スレッドを束ねる |
| Thread | コミュニティに属する議論の単位。タイトルを持つ |
| Post | スレッド内の発言。フラットに時系列で並ぶ（ネストなし） |

## 7. 画面

| 画面 | 役割 | 内容 |
|---|---|---|
| ホーム | 発見 | 全コミュニティを横断したスレッド一覧 |
| コミュニティ一覧 | 入口 | コミュニティの一覧と作成 |
| コミュニティページ | 一望 | そのコミュニティのスレッド一覧とスレッド作成 |
| スレッドページ | 参加 | 投稿一覧（時系列）と投稿フォーム |

## 8. 機能スコープ

| 対象 | 作成 | 閲覧 | 修正 | 削除 |
|---|---|---|---|---|
| コミュニティ | ○ | ○（一覧／個別ページ） | ○ | ○ |
| スレッド | ○ | ○（ホーム横断一覧／コミュニティ内一覧） | ○ | ○ |
| 投稿 | ○ | ○（スレッド内でフラット表示） | ○ | ○ |

- 修正・削除は作成者本人のみが行える。管理者ロールは設けない。
- スレッド作成時は、タイトルと最初の投稿（本文）を同時に入力する。
- スレッドの修正対象はタイトル、投稿の修正対象は本文とする。
- 子要素を持つコミュニティ・スレッドは削除できない（コミュニティはスレッドが、スレッドは投稿が残っていれば削除不可）。
- 削除は物理削除とし、修正・削除の履歴は残さない。
- スレッド一覧は最終投稿順（新しい投稿があったスレッドが上）で並べる。
- ホームのスレッド一覧は全コミュニティ横断とし、ユーザーごとの出し分けは行わない。

## 9. 非スコープ

- 投票（up/down）とスコアによる並び替え
- 投稿のネスト（返信への返信）
- 画像・リンク投稿
- コミュニティへの参加（join）とパーソナライズされたホーム
- モデレーション、管理者機能
- 検索
- 通知
- 未ログインでの閲覧、一般公開
- 独自の認証機能（認証は Cloudflare Access に任せる）
- 修正・削除の履歴管理
- 大規模運用、長期運用、収益化、モバイルアプリ

## 10. 技術方針

- Cloudflare のフリープランの範囲で構成する。
- Workers と D1 を中心とし、必要に応じて KV などを追加する。
- 認証は Cloudflare Access に任せ、アプリ側は Access が付与するユーザー情報（メールアドレスなど）でユーザーを識別する。
- 無料枠の日次上限（リクエスト数、D1 の行読み書き数）や CPU 時間の制限に収まる設計とする。具体的な上限値は最新のドキュメントで確認する。

## 11. 決定事項

| 項目 | 決定 |
|---|---|
| 構図 | コミュニティ → スレッド → 投稿（フラット） |
| ホームの一覧 | 全コミュニティ横断 |
| スレッド一覧の並び順 | 最終投稿順 |
| 投票 | なし |
| 投稿のネスト | なし |
| コミュニティ作成 | あり |
| 修正・削除 | あり（作成者本人のみ、管理者ロールなし） |
| スレッド作成 | タイトルと最初の投稿を同時に入力 |
| 子要素がある場合の削除 | 削除不可 |
| 削除方式 | 物理削除（履歴なし） |
| 公開範囲・認証 | Cloudflare Access の内側。特定ドメインの Google アカウントのみログイン可 |
